# Spike: ERPNext как учётное ядро — результат

- **Дата:** 2026-10-05
- **Проект:** finance-director
- **Вердикт: ERPNext подтверждён как учётное ядро.** Цифры сошлись с независимой моделью до рубля.

## Что проверялось

Гипотеза: готовое учётное ядро ERPNext закрывает вопросы, которые иначе пришлось бы
писать самим, а собственный слой финдира становится надстройкой.

Проверка на реальных данных сентября 2026 («Точка №1»).

## Что сделано

1. **Компания создана через мастер настройки.** Прямое создание через API упало
   (`Could not find Warehouse Type: Transit`) — фикстуры грузит не `after_install`,
   а мастер. Программный вход найден в исходниках:
   `erpnext.setup.setup_wizard.setup_wizard.setup_complete(args)`
   с пометкой *«Only for programmatical use»*. Скрипт: `scripts/spike_erpnext.py`.

2. **Сентябрь записан одной сбалансированной проводкой** (`ACC-JV-2026-00001`,
   проведён, docstatus 1). Скрипт: `scripts/spike_september.py`.

3. **Результат сверен двумя независимыми путями** — по проводкам GL Entry
   и отчётом ERPNext «Profit and Loss Statement». Скрипт: `scripts/spike_finalize.py`.

## Сверка

| Источник | Доход | Расход | Результат |
|---|---|---|---|
| Наша модель (`scripts/model.py`) | 182 570 | 209 204 | **−26 634 ₽** |

| Отчёт P&L в ERPNext | 182 570 | 209 204 | **−26 634 ₽** |

Отчёт ERPNext, дословно:

```
Total Income    182570.0 RUB
Total Expense   209204.0 RUB
Net Profit      -26634.0 RUB   indicator: Red
```

**Расхождение — ноль.** Два независимых пути расчёта дали одно число.

## Что это доказывает

- ERPNext **принимает наш сценарий** учёта без доработок: проводка, план счетов,
  кост-центр, фискальный год, отчёт о прибылях и убытках.
- **P&L строится из проводок**, а не вводится руками — значит, любая операция
  автоматически попадает в отчётность. Это ровно то, чего нет у нашего `model.py`.
- Готовые справочники (239 единиц измерения, 5 складов, 69 счетов) — это то,
  что пришлось бы писать самим.
- Сверка с независимой моделью до рубля подтверждает, что наш расчёт корректен,
  а ERPNext считает так же.

## Что НЕ проверено

- **Себестоимость 45 643 — допущение 25% от оборота**, не первичка. Ключевая дырка
  проекта остаётся: без фактической себестоимости результат −26 634 ₽ условен.
- **Бюджет и обязательства** (календарь платежей) — не проверялись. Следующий шаг.
- **Роли и права** (финдир отдельным агентом, ADR 001) — не проверялись.
- **Импорт дневных данных** — не проверялся, дневной выгрузки нет.
- **Мультиточка** (ADR 002) — не проверялась, работали на одной точке.

## Вывод

Гипотеза подтверждена. ERPNext годится как учётное ядро: он принимает наши данные,
строит отчётность из проводок и даёт справочники, которые иначе писались бы с нуля.
Собственный слой финдира имеет смысл делать надстройкой — предложения, календарь
платежей, разбор отклонений, — а не заменой учёта.

## Как воспроизвести

```bash
cd C:/Users/user/dev/_install/frappe_docker
docker compose -f pwd.yml -f pwd-local.yml up -d

# компания и фикстуры (внутри контейнера)
docker cp erp_setup.py frappe_docker-backend-1:/tmp/
docker exec frappe_docker-backend-1 sh -c \
  "cd /home/frappe/frappe-bench/sites && ../env/bin/python /tmp/erp_setup.py"

# сентябрьские данные
cd C:/Users/user/dev/finance-director/scripts
python spike_september.py
python spike_finalize.py
```

Скрипты: `scripts/spike_erpnext.py`, `scripts/spike_september.py`,
`scripts/spike_finalize.py`, `_install/erp_setup.py`, `_install/spike_final.py`.
