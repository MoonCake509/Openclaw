# Выгрузка данных на сервере — 2026-10-06

Пайплайн выгрузки перенесён с ноутбука на сервер и работает автономно.

## Главное: почему НЕ headless

**У Вендора антибот, который запрещает вход под не-пользовательским профилем браузера.**
Проверено: свежий контекст с перенесёнными cookies Вендор не пускает — страница остаётся
неавторизованной. То же с LifePay: cookies сами по себе дают `401 Unauthorized`.

Поэтому схема такая:

```
Chrome с РАБОЧИМ профилем  →  владелец входит руками  →  агент подключается по CDP (порт 9222)
   C:\Users\user\AppData\Local\hermes\chrome-auth
```

Браузер **не headless** и **не временный профиль**. Это единственная схема, которая проходит
антибот Вендора.

Скрипт запуска: `_install/open_sites.ps1`.

## Где хранится авторизация

| Система | Где лежит сессия | Переживает перезапуск |
|---|---|---|
| LifePay | `localStorage` ключ `[хранилище токена]` — зашифрованный блоб (CryptoJS, `U2FsdGVkX1` = «Salted__»), ~80 КБ | да — записан в LevelDB профиля |
| Вендор | cookies Яндекс ID (`.yandex.ru`: `[cookie]`; `.passport.yandex.ru`: `[cookie]`, `lah`) | да — истекают в 2028 |

**Что НЕ работает:** скопировать cookies и запустить headless. LifePay отдаёт `401`, Вендор не узнаёт сессию.

Токен LifePay (`Authorization: Bearer`, 44 символа, не JWT) живёт внутри `[хранилище токена]`; отдельного
refresh-эндпоинта у приложения нет — на логин оно ходит только при отсутствии валидного `[хранилище токена]`.

### 3. ВАЖНО: сдвиг дат в API LifePay

API `reports/revenue/periods` **метит день на единицу раньше**, чем интерфейс.

Проверено на четырёх днях — совпадение точное:

| API | База (МСК) | Сумма |
|---|---|---|
| 2026-09-30 | 2026-10-01 | 5 625,00 ₽ |
| 2026-10-01 | 2026-10-02 | 4 221,00 ₽ |
| 2026-10-02 | 2026-10-03 | 5 590,00 ₽ |
| 2026-10-03 | 2026-10-04 | 2 710,00 ₽ |

**Правило: дата МСК = дата API + 1 день.** При импорте дату приводить к МСК.
Проверка — `probe_shift.py`.

### 5. Расхождение касса / позиции

Сумма по позициям 4 119,00 ₽ против выручки кассы 4 519,00 ₽ — **разница 400,00 ₽**.

Это **разовый сбой системы LifePay** (недосчитала 400 ₽ при формировании отчёта по операциям),
а не разница базисов дат. Решение владельца: сумму досчитать.

Как реализовано: расхождение **не прячется**, а пишется явной строкой
`Корректировка до кассы` в `dish_sales`, чтобы сумма по позициям сходилась с кассой
и след расхождения сохранялся. Если расхождение есть, в `daily_context` добавляется
предупреждение `dish_vs_cash`.

### 6. Пайплайн и крон

Один вход — всё делает сам:

```
python daily_pipeline.py                    # за вчера
python daily_pipeline.py --date 2026-10-05  # за конкретный день
```

Шаги: проверка Chrome (поднимает, если мёртв) → выручка LifePay → продажи по блюдам →
доставка Вендора → запись в базу + `daily_context` → 3 дашборда → сохранение состояния сессии.

Прогон за 05.10 занял **64 секунды**.

Крон создан — **ежедневно в 07:00**, первый запуск 2026-10-07 07:00:

```
job_id: 3d2d5b7dc8df
name:   finance-director: ежедневная выгрузка
```

Забирает данные за вчерашний день и присылает отчёт с тремя дашбордами.
Если сессия истекла — сообщает владельцу, что нужно войти заново в окне Chrome; сам логин не подбирает.
